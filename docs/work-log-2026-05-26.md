## 1. 배경 & 출발점 정정

로드맵 "다음 세션 작업: 마이그 054 — community_* RLS strict" 를 진행하려 했으나, 실제 repo 에서 **054 는 이미 `landing_assets_bucket`** 이 사용 중이었음. 로드맵이 계획한 community RLS 는 미진행 상태 → 다음 빈 번호 **055** 로 작업.

또한 로드맵 진단(2026-05-13)이 실제 스키마와 일부 달랐음:
- 로드맵이 언급한 `community_contacts` 는 **존재** (단, 추적된 마이그레이션 없이 prod 에만 있는 드리프트)
- `community_users` 도 동일하게 추적 마이그레이션 없음
- community 클러스터는 `members`/`trainers` 와 **별개인 자체 `community_users` 가입 시스템**

## 2. 인증 모델 확인 (strict RLS 가능 판정)

`CommunityPortal.jsx` 가 Supabase OAuth(Google/Kakao) 사용 → `community_users.auth_id` 로 본인 행 매핑. trainers/members(050/051) 와 동일하게 **auth.uid() 기반 strict RLS 가능** 확인.

⚠️ 단, 이 DB 의 `community_users.auth_id` 는 **TEXT** 타입 (trainers/members 는 uuid 였던 것과 다른 드리프트) → 모든 비교를 `auth.uid()::text = auth_id` 로 캐스팅.

## 3. 발견한 핵심 문제 (R1 P0)

`community_users` 에 정책이 **10개** 공존 — 그중 추적 안 된 `{public}` 정책들:
- `public read/insert/update community_users`
- `cu_select_public / cu_insert_self / cu_update_self / cu_delete_self`

RLS 는 permissive 정책의 OR 평가라, 이 `{public}` 정책 때문에 **anon key 만으로 전 회원 PII(이름/전화/카카오링크) + admin_permissions 조회/변경** 가능. 처음 작성한 마이그가 지운 이름(`allow_all_community_users`)이 실제로는 없어서 누출이 지속됐음.

## 4. 해결 — 055_community_rls_strict.sql

대상 5개 테이블: `community_users / community_posts / community_contacts / market_purchases / market_item_contents`

- **이름 무관 전부 제거 후 재생성**: `pg_policies` 동적 루프로 5개 테이블의 모든 기존 정책 DROP → 추적 안 된 `{public}` 드리프트도 확실히 제거
- **strict 정책 재생성** (auth.uid()::text 기반):
  - users: SELECT 는 authenticated 전체, INSERT/UPDATE 는 본인(auth_id) 만
  - posts: SELECT authenticated, 쓰기는 작성자(user_id) 만
  - contacts: 요청자 본인 OR 게시글 작성자만
  - market_*: 구매자/판매자 본인만
- **self-escalation 방지**: `REVOKE UPDATE (admin_permissions, role) ON community_users` → 본인 행이라도 권한/역할 변경 불가. admin SECURITY DEFINER RPC(향후 056)는 GRANT 영향 안 받음
- **contact_count 트리거**: 비작성자가 작성자 게시글 카운터를 올려야 하므로, 작성자-only RLS 와 충돌하는 클라이언트 직접 UPDATE 대신 `bump_community_contact_count()` (SECURITY DEFINER) AFTER INSERT 트리거로 이동

### CommunityPortal.jsx
- `sendContact()` 의 클라이언트측 `contact_count` UPDATE 제거 (트리거가 처리 → 중복 카운트 방지)
